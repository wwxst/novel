# 09 · 分阶段开发计划、估算与验收门

> 估算口径：1 人日 = 6 小时有效产出；工程师熟悉本项目领域；不含反复需求变更。
> 该数字用于排期与取舍，不是交付承诺；实际以每个阶段的门槛验收为准。

## 1. 范围分层（先定做多大，再排期）

| 层级 | 内容 | 估算（人日） | 说明 |
|---|---|---:|---|
| **Tier A · MVP 内核链路** | 启动、路由、设计 token、Mock 数据、书架/首页入口、详情、阅读器（分页+基础 UI+设置+进度保存/恢复）、错误/空态、三端可运行 | **120–150** | 阶段二；"能从头到尾读一本书" |
| **Tier B · 11 屏完整版（v1）** | 书城/频道/榜单/分类/搜索 6 态/书架 4 子 tab/我的/历史/消息/设置 + 阅读器 5 翻页/目录/菜单/夜间/图片/缓存 | **+200–260（累计约 320–410）** | 阶段三；达到可自用的完整阅读产品 |
| **Tier C · 完整产品** | Tier B + 离线下载、TTS、书签/笔记、评论、账号/同步（需后端）、分类真实结构等 P1/P2 域 | **+150–250（累计约 470–660）** | 阶段四/五；需逐项批准，非一次承诺 |

> 口径说明：既有工程的纯代码迁移按行数估算约 306 人日（偏乐观下界）；独立质疑复核后，计入 Web 专有（镜像/字体/SW/双渲染器）、justify 标定、测试重建、真机修复与 15% 缓冲，完整 11 屏三端范围约 **420–640（P50≈500）**。上表 Tier B+C 与之同量级。**估算不是承诺**，每个阶段按门槛验收。

> 结论：只做 Tier A 是一个可演示、可用的内核，但**不是完整产品**；Tier B 才是"自己的日常阅读器"；Tier C 需要后端与长期投入。建议按 A → B → C 推进，每个层级结束由用户决定是否继续。

## 1.1 域 × 阶段 × 入口处置

> 规则：11 屏内**可见入口**必须三选一：真实实现 / 显式禁用并说明 / 删除入口。禁止静默 toast 或"敬请期待"占位。范围外域在 README 非目标与本表登记。

| 域 | 现有可见入口 | 阶段 | 处置 |
|---|---|---|---|
| 启动/首启（权限、18+、隐私、兴趣） | 有 | Tier A（最小）+ Tier B（完整） | 真实实现；未成年模式 Tier C 或上架前 |
| 主框架/tab/返回 | 有 | Tier A | 真实实现 |
| 书城/频道/榜单/分类 | 有 | Tier A（推荐/榜单入口）+ Tier B（完整 8 频道/分类/榜单筛选） | 真实实现 |
| 搜索（6 态） | 有 | Tier A（入口/结果）+ Tier B（联想/历史/热词/排序） | 真实实现 |
| 详情 | 有 | Tier A | 真实实现 + 显式"开始阅读"按钮 |
| 阅读器 | 有 | Tier A/B | 真实实现 |
| 书架/历史 | 有 | Tier A（书架）+ Tier B（4 子 tab/历史） | 真实实现 |
| 我的/设置 | 有 | Tier B | 真实实现 |
| 消息 | 有（我的消息） | Tier B 最小（mock 列表） | 真实列表（mock 数据），不伪造推送 |
| 听书/TTS | 有（胶囊/球） | Tier B 最小（系统 TTS + 降级） | 保留入口；引擎不可用时明确提示 |
| 评论/段评 | 有（书评/评论区） | Tier B 最小（只读书评 mock） | 真实列表；发布/段评 Tier C |
| 下载/离线 | 有（菜单下载） | Tier B 最小（最近 N 章 + 已读缓存 + 离线态） | 真实缓存；下载管理 Tier C |
| 登录/账号 | 有（登录条） | Tier C（需后端） | 服务端未实现前显示"账号功能未开放"说明页，不做假登录 |
| 圈子/社区 | 有（圈子 tab） | Tier C | v1 隐藏 tab 或明确禁用说明，不放空页 |
| 划词/笔记/段评 | 阅读器长按 | Tier C（最小复制/划线可提前） | 需用户签字确定范围 |
| 短剧/漫画/游戏/商城/支付/广告/创作/容器/AI | 部分频道入口 | 范围外 | 删除入口或明确"不支持"；逐项登记，不排期 |
| 桌面组件/深链/通知 | 无 | Tier C/P2 | 平台特性，后置 |
| 未成年模式 | 无 | Tier C 或上架前 | 合规要求，需单独立项 |

## 2. 阶段计划

### 阶段一：方案（当前）
- 产出：本仓库 docs 全部方案文档、质疑记录与裁决、风险/决策清单。
- 出口：用户明确批准；未批准不写产品代码。

### Gate 0：工具链与关键探针（批准后第 1 周，3–5 人日）
| 探针 | 通过标准 |
|---|---|
| Flutter/Android SDK 配置 | `flutter doctor` Android 绿；`flutter build apk --debug` 成功（本机已实测可构建） |
| Web 构建 | `flutter build web --release --wasm` 成功；Edge 可打开；产物体积脚本可跑 |
| 字体子集 | 生成 ≤1.2MB woff2 子集；金标 94 行不变；许可证随附 |
| drift Web | 体积增量 ≤1.5MB gzip、初始化 ≤300ms；否则切 sembast |
| 金标复现 | 纯 Dart 重分页得到 8 页/94 行/锚点一致 |
| Web 文本镜像 PoC | Canvas 上文字可选中/复制，span 坐标与分页一致（≤0.5dp） |
| 仓库骨架 | 单包、arch_check、lint、token 生成、CI 脚本空转 |

**Gate 0 不通过则不进入编码。**

### 阶段二：Tier A · 最小完整链路（约 6 个迭代，120–150 人日）
| # | 迭代 | 内容 | 主要产出 |
|---|---|---|---|
| S0 | 骨架与门禁 | 单包、路由表、AppGraph、token、mock 搬运、arch_check、错误模型；**三个硬探针**（依赖离线解析 / drift Web 体积与初始化 / 字体子集） | 可启动空壳 + 3 tab |
| S1 | 数据层 | 模型、Mock API、drift/KV、仓储、manifest v2 | 数据可读写、契约测试 |
| S2 | 阅读器算法 + justify | 断行/装页/锚点/重排 + **两端对齐 PoC** + 金标 | 8 页/94 行 + 右墨迹 ≤2px |
| S3 | 阅读器 UI | 页面绘制、翻页（覆盖/平移/上下）、菜单、目录、设置、进度、空章/错误态 | 可连续阅读、设置生效、进度恢复 |
| S4 | 浏览链路 | 首页/书架/详情（显式开始阅读按钮）/搜索入口/设置最小实现 | 选书 → 详情 → 阅读闭环 |
| S5 | 三端收口 | Web 镜像层（整章）、Android 构建、Web 体积、软件 SW 最小版、证据与验收 | 三端可运行 + 未验证清单 |

**S0 硬前置**（任一不通过不得进入编码）：① 9 个直接依赖与传递依赖预拉进 pub cache，`flutter pub get --offline` 通过；② 含 drift+sqlite3 的空 Web 包体积增量 ≤1.5MB gzip、`open()` ≤300ms；③ 字体子集成 ≤1.2MB 且金标 94 行不变。探针结果写回 `docs/07-platform-and-performance.md` 与 `docs/06-data-and-backend.md`。

阶段二验收（硬）：真实数据闭环；阅读器金标；返回/重启恢复；无 P0/P1；三端矩阵齐全（iOS 标 unverified）。

### 阶段三：Tier B · 11 屏完整版（约 8–10 个迭代，+200–260 人日）
- 阅读器补全：5 种翻页、仿真页动画、图片加载、评论面板、TTS 球、书签预留、长章性能。
- 页面补全：频道 8 页、完整榜单 + 分类筛选、分类、搜索 6 态、书架 4 子 tab、我的、历史、消息、设置。
- 离线最小路径：最近 N 章 + 已读章节缓存、离线态文案与验收；Web 外壳 SW（8–12 人日）。
- 登录/圈子/评论发布等无后端能力：显式禁用说明页或隐藏入口，不伪造。
- 每模块流程：已有成果对照 → 实现 → 测试 → 质疑 → 修复 → 验收。
- 遗留缺陷 18 条逐项给出"修复/明确差异/用户豁免"结论。

### 阶段四：Tier C · 扩展（按批准的子项推进，+150–250 人日）
建议顺序：离线下载 → TTS 播放器 → 书签/笔记/划线 → 后端与账号同步 → 评论 → 分类真实结构 → 其它 P2 域。
**每个子项单独立项、单独验收；不一次性承诺全部 P2。**

### 阶段五：硬化与发布（30–50 人日）
- 真机性能、内存、长时间阅读、异常恢复、弱网、1.3× 字号、平板/桌面。
- 全量回归、截图/度量基线、发布包体积与签名、隐私与合规检查。
- 独立验收 + 用户签字。
- **无设备出口规则**：没有 Android 真机/模拟器或 macOS 时，阶段五**不得判定通过**；报告必须输出 `unverified_cells=NNN/315` 与逐格状态，设备到位后重开验收。

## 3. 并行与依赖

| 工作线 | 依赖 | 可并行 |
|---|---|---|
| 阅读器算法 + UI | 数据模型、设计 token | S1 后与浏览页并行 |
| 浏览页（首页/搜索/详情/书架/我的） | 数据层、组件库 | 相互独立，按文件作用域拆分 |
| Web 适配（镜像层/字体/构建） | 阅读器分页输出 | 可与 S3 并行 |
| 测试与证据 | 各模块 | 持续进行 |

写作用域规则：同一目录同一时间只允许一个执行者；共享文件（路由表、token、模型）由主控或指定负责人独占修改。

## 4. 关键路径与风险缓冲

关键路径：**Gate 0 → S2 算法 → S3 阅读器 UI**。算法口径未冻结就写 UI，返工是整模块级；因此 S2 必须先出金标再开 S3。

缓冲建议：Tier A 估算 +20% 缓冲；阅读器模块 +30%（Web 镜像/字体/iOS 未知）。若 Gate 0 发现字体或 Web 方案不成立，回到方案层修订，不带病编码。
